# Exercise 3 — Plan the Migration

> **Goal:** Use GitHub Copilot Chat to produce a phased implementation plan and a file-level task list that will drive the hands-on migration in Exercises 4 and 5. The `quarkus-migration` skill is auto-invoked — no file attachment needed.

> **Time:** ~8 minutes &nbsp;|&nbsp; **Prerequisite:** Custom instructions and `quarkus-migration` skill created ([Exercise 2](exercise-2.md)) &nbsp;|&nbsp; **Track:** Required for Exercises 4 and 5

---

## Context

The gap report tells you *what* changes. The principles tell you *how* each change must be made. This exercise produces the *sequence*: a phased plan that keeps the project in a buildable state at every step, plus a task list that assigns every change to a specific file with clear acceptance criteria. These two artefacts are your implementation backlog for the next two exercises.

The five migration phases, in order:

| Phase | Files | Why This Order |
|-------|-------|----------------|
| 1 | `pom.xml` + `application.properties` | Foundation — Quarkus can't start until the build and config are in place |
| 2 | `Product.java` | Model must compile under Jakarta before anything that depends on it can change |
| 3 | `ProductRepository.java` | Repository depends on the model; service/controller depend on the repository |
| 4 | `MainController.java` | Controller depends on both model and repository |
| 5 | `SwaggerConfig.java` + `AppException.java` + `CrudApplication.java` | Cleanup — these either become unnecessary or need minor adaptation |

---

## Step 1 — Generate the Plan

> The `quarkus-migration` skill and `.github/copilot-instructions.md` are loaded automatically — Copilot already knows the project context and migration rules.

1. Open **Copilot Chat** in VS Code (agent mode)
2. Send the following prompt:

```
Create a technical implementation plan for migrating this Spring Boot 2.x Product CRUD service
to Quarkus 3.x, following the quarkus-migration skill rules.

The plan must cover:
- Implementation sequence: why Phase 1 (build + config) must come before model, which must
  come before repository, which must come before controller, which must come before cleanup
- How to keep the project in a buildable state at each phase — i.e. what compile errors to
  expect mid-migration and how to resolve them before moving to the next phase
- How to verify the app is working correctly after Phase 1 (quarkus:dev starts) and after
  Phase 5 (all five CRUD endpoints respond correctly via Swagger UI)

Format the plan as:
## Phase N — <name>
### Files Changed
### What Changes
### How to Verify
```

3. Review the plan. Each phase should have clear file targets, specific changes, and a verifiable outcome.

---

## Step 2 — Generate the Task List

Still in the same Copilot Chat conversation, send:

```
Now generate a task list from this plan. For each task include:
- Task ID (T1, T2, T3 ...)
- File path (relative to project root)
- Specific change description (be precise — name the exact annotation, property key, or class)
- Acceptance criteria (one sentence: what does "done" look like for this task?)
- Phase number

Order tasks within each phase so earlier tasks in the phase don't block later ones where
possible. Flag tasks that can be done in parallel with [P].

Format as a markdown table with columns: Task | File | Change | Acceptance Criteria | Phase
```

---

## Step 3 — Save the Task List

Ask Copilot to save the task list as a file in the workshop folder:

```
Save the task list table as workshop/migration-tasks.md with the following front matter:

# Migration Task List
> Generated by GitHub Copilot | Spring Boot 2.x → Quarkus 3.x | Product CRUD Service

Then include the task table.
```

Review and **accept** the file.

---

## Step 4 — Validate the Plan and Task List

Confirm the plan covers all five phases:

| Check | Expected |
|-------|----------|
| Phase 1 present | `pom.xml` + `application.properties` targeted |
| Phase 2 present | `Product.java` — `javax` → `jakarta` import changes |
| Phase 3 present | `ProductRepository.java` — `JpaRepository` → `PanacheRepository` |
| Phase 4 present | `MainController.java` — all Spring MVC annotations replaced |
| Phase 5 present | `SwaggerConfig.java` deletion, `AppException.java` update, `CrudApplication.java` deletion |
| Verification steps present | `mvn quarkus:dev` check after Phase 1; Swagger UI check after Phase 5 |
| Task list saved | `workshop/migration-tasks.md` exists in the repository |

> If any phase is missing or a task is too vague, ask Copilot to expand that section before moving on. Vague tasks lead to inconsistent code generation in Exercises 4 and 5.
